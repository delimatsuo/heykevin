## What changed

New-account onboarding now asks which country issued the mobile number before
using the number form. A device's region is only a labeled suggestion; an
unsupported device region is never silently replaced with the United States.

The selected number country is checked before a new account can enter phone
setup. An unavailable or qualification-required country receives a dedicated,
localized screen that names the country, explains that availability follows the
number's issuing country, and lets a traveler choose a different number country.
It does not show a phone form, provisioning action, purchase action, or create
an account.

The existing-member path remains available for account recovery. If Apple
sign-in identifies a person as new, they must still choose and pass a
number-country availability check before reaching the phone form; Back returns
to sign-in instead of bypassing that check. Final client and server admission
guards remain in place before contractor creation and trial effects.

The result is covered by a dedicated Brazilian Portuguese review fixture,
Spanish and Brazilian Portuguese localizations, device-region tests, market
admission tests, and a regression test for the direct-sign-in Back route.

## Limits retained

The current production backend still has the legacy markets-route behavior:
when it returns a route-level 404, the app deliberately admits **US only** and
keeps Canada, Brazil, the United Kingdom, and other countries unavailable. This
package improves the explanation and removes the false US assumption; it does
not turn on a market or bypass carrier/provider qualification.

No live phone call, carrier-forwarding action, number purchase, SMS, App Store
public release, external TestFlight delivery, or Cloud Run deployment occurred.
All archive, IPA, extraction, and Apple response files were confined to the
configured temporary directory and removed after readback.
